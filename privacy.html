מדיניות פרטיות

עודכן לאחרונה: 7 בספטמבר 2026

מדיניות זו מתארת כיצד AvielPC ("AvielPC", "אנחנו") מטפלת במידע המתקבל משירותי Google כאשר מערכות ואתרי עסקים המשתמשים בתשתית שלנו מאפשרים למשתמש לחבר את חשבון Google שלו.

1. מי אנחנו ומהו השירות

AvielPC היא ספקית טכנולוגיה המפתחת ומתחזקת מערכות עבור עסקים. שירות Google Integration הוא תשתית תוכנה המאפשרת למערכות עסקיות להתחבר לשירותי Google באמצעות OAuth.

לכל עסק עשוי להיות אתר ו-Backend נפרדים. החיבור ל-Google מתבצע במסגרת המערכת העסקית שאליה המשתמש מחובר.

2. איזה מידע מתקבל מ-Google

בהתאם להרשאות שהמשתמש מאשר ולפונקציות שהמערכת מפעילה, המידע עשוי לכלול:

  • מידע בסיסי של חשבון Google: מזהה חשבון, כתובת דוא"ל ופרטי פרופיל בסיסיים, בהתאם להרשאות OAuth.
  • Google Contacts: מידע מאנשי הקשר של המשתמש, בהתאם להרשאת הקריאה שאושרה.
  • Google Calendar: מידע הנדרש ליצירה ולעדכון של אירועי Calendar בהתאם לפעולות שהמשתמש או המערכת העסקית ביקשו לבצע.
  • OAuth credentials: לאחר אישור המשתמש, Google עשויה לספק Refresh Token ו-Access Token הדרושים להמשך גישה מורשית. ה-Refresh Token אינו נשלח לדפדפן כמידע לשימוש המשתמש.

3. כיצד אנו משתמשים במידע מ-Google

מידע מ-Google משמש אך ורק כדי לספק את הפונקציונליות שהמשתמש או המערכת העסקית ביקשו להפעיל, כגון סנכרון עם Google Calendar, יצירה ועדכון של אירועים, קריאת אנשי קשר כאשר תכונה זו נדרשת, וזיהוי חשבון המשתמש.

אנו לא מוכרים Google user data, לא משתמשים בו לפרסום ממוקד, ולא מעבירים אותו למתווכי מידע. Google user data אינו משמש לאימון או לשיפור מודלים כלליים ולא-אישיים של AI/ML.

4. אחסון Refresh Token

במימוש הנוכחי, ה-Refresh Token של חיבור Google נשמר בצד השרת בקובץ ייעודי בשם data/google-calendar-token.json. הקובץ נמצא מחוץ לקוד המקור ולמאגר הקוד, ונשמר בנפח נתונים נפרד של השרת.

לקובץ מוגדרות הרשאות מערכת מוגבלות (0600), כך שהגישה אליו מוגבלת למשתמש המערכת המתאים. בשלב זה הקובץ עצמו אינו מוצפן ברמת הקובץ. אנו מגנים עליו באמצעות הרשאות מערכת, בידוד סביבת השרת ובקרות גישה.

ספריית Google משתמשת ב-Refresh Token כדי לקבל Access Token חדש לפי הצורך. ה-Access Token אינו נשמר בדפדפן ואינו מיועד להיחשף למשתמש או לאתר שאינו זקוק לו.

5. מידע הנשמר במסד הנתונים

במימוש הנוכחי נשמר במסד הנתונים, בין היתר, מזהה Google Calendar event (google_event_id) המקשר בין הזמנה במערכת העסקית לבין האירוע המתאים ב-Google Calendar. מזהה זה משמש כדי לאפשר עדכון או ביטול של האירוע הנכון.

6. שיתוף מידע

מידע מ-Google אינו נמכר ואינו משותף לצורכי פרסום. מידע עשוי להיות מעובד באמצעות ספקי תשתית וטכנולוגיה הדרושים להפעלת השירות, כגון אחסון ושרתים, ורק במידה הנדרשת למתן השירות, אבטחתו ותחזוקתו.

כאשר מערכת עסקית מופעלת עבור עסק מסוים, המידע המשויך למשתמש מעובד במסגרת אותה מערכת עסקית. אין כוונה להעביר Google user data של עסק אחד למערכת של עסק אחר.

7. אבטחת מידע

אנו משתמשים ב-HTTPS, הרשאות מערכת מוגבלות, הפרדת קבצי נתונים מהקוד, בקרות גישה ושיטות אבטחה מקובלות כדי להגן על מידע והרשאות.

למרות אמצעי האבטחה, אין מערכת שניתן להבטיח שהיא חסינה לחלוטין מפני כל אירוע אבטחה.

8. שמירת מידע ומחיקה

מידע נשמר כל עוד הוא נדרש להפעלת התכונה שלשמה הוא נאסף, לצורך תפעול, אבטחה ועמידה בדרישות משפטיות, בהתאם לצורך.

כאשר המשתמש מנתק את חיבור Google במערכת, ניתן למחוק את ה-Refresh Token המקומי ואת נתוני החיבור המקומיים בהתאם למימוש המערכת. מחיקת קובץ הטוקן מפסיקה את השימוש המקומי בו, אך אינה מבטלת כשלעצמה את ההרשאה שנתן המשתמש ל-AvielPC ב-Google.

9. ביטול הרשאה ב-Google

המשתמש יכול לבטל את ההרשאה שנתן ליישום דרך הגדרות חשבון Google שלו, תחת ההרשאות של אפליקציות ושירותים של צדדים שלישיים. לאחר ביטול ההרשאה, המערכת לא אמורה להמשיך להשתמש בהרשאה שבוטלה.

10. Google API Services User Data Policy

השימוש שלנו במידע המתקבל מ-Google APIs יעמוד ב-Google API Services User Data Policy, לרבות דרישות Limited Use. אנו מגבילים את השימוש ב-Google user data למטרות המתוארות במדיניות זו ולפונקציונליות שהמשתמש ביקש להפעיל.

11. שינויים במדיניות

אנו עשויים לעדכן מדיניות זו כאשר השירות, אופן עיבוד המידע או הדרישות המשפטיות משתנים. הגרסה העדכנית תפורסם בעמוד זה.
